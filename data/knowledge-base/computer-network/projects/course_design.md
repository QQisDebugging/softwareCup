## 课程设计定位

本课程设计面向计算机网络课程末端综合实践，要求学生围绕网络开发、协议分析、网络服务或 Web 网络应用完成一个可运行的小型系统。课程设计强调从网络理论到工程实现的迁移，包括需求分析、模块划分、通信协议设计、程序实现、测试验收和报告撰写。

## 时间与组织方式

- 建议安排在第 18-19 周。
- 学生可任选一题独立完成。
- 也可 2-3 人组成小组合作完成，小组应根据题目难度和工作量划分相对独立的模块。
- 可自拟题目，但题目应与网络开发、网络协议、网络服务或网络安全工具密切相关。

## 成绩构成

- 系统验收：50%
- 课程设计报告：50%

## 通用过程要求

1. 明确选题背景、应用场景和系统目标。
2. 完成需求分析，列出核心功能、扩展功能和非功能要求。
3. 进行模块划分，说明每个成员或每个模块的职责。
4. 设计通信流程、数据结构、数据库模型或协议处理逻辑。
5. 完成可运行程序，实现关键功能。
6. 进行测试，提供截图、日志、抓包结果或演示记录。
7. 撰写课程设计报告，说明设计思路、实现方法、关键代码、测试结果和问题反思。

## 推荐选题方向

课程设计选题可分为四类：

- Socket 通信类：实时通信工具、网络文件传输、广播通信、网络版小游戏。
- Web 应用类：网上图书馆、网上书店、报名查分系统、新闻发布系统、留言簿。
- 网络工具类：嗅探器、端口扫描工具。
- 网络服务类：简易 Web 服务器。

## 报告建议结构

1. 题目名称与成员分工
2. 需求分析
3. 系统总体设计
4. 模块设计与关键流程
5. 通信协议或数据库设计
6. 关键代码说明
7. 测试方案与结果
8. 运行截图或抓包截图
9. 问题分析与改进方向
10. 总结

## 个性化指导策略

- 网络基础薄弱学生：优先推荐 Web 应用类或简易通信类题目，并生成协议流程图与接口清单。
- 编程能力较强学生：优先推荐嗅探器、端口扫描、简易 Web 服务器等系统底层题目。
- 团队协作型学生：优先推荐网上图书馆、网上书店、报名查分系统等可清晰拆分前端、后端、数据库模块的题目。
- 对网络协议感兴趣学生：优先推荐实时通信、文件传输、广播通信、TCP/UDP 分析相关题目。

## 验收关注点

- 程序是否能独立运行。
- 是否体现计算机网络课程知识，例如 Socket、TCP/UDP、HTTP、IP、端口、协议解析等。
- 是否有清晰的模块划分和关键流程说明。
- 是否有测试结果和异常情况处理。
- 报告是否能解释设计选择，而不只是贴代码和截图。
