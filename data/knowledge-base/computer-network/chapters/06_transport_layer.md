# 第六章 传输层

## 学习目标

- 理解传输层为什么提供进程之间的通信。
- 掌握可靠传输、流量控制和拥塞控制的基本思想。
- 区分 TCP 与 UDP 的典型使用场景。

## 先修知识

- 网络层主机到主机通信
- IP 地址、路由和分组转发
- 基本应用进程概念

## 核心概念

- 进程之间的通信
- 端口
- 套接字
- 可靠传输
- 流量控制
- 拥塞控制
- TCP
- UDP

## 关键知识点

- 网络层解决主机到主机的传输问题，传输层进一步解决进程到进程的交付问题。
- 端口号用于标识主机上的具体应用进程，套接字通常由 IP 地址和端口共同参与描述。
- 可靠传输通过序号、确认、重传和定时器等机制降低丢包、乱序和重复带来的影响。
- 流量控制关注接收方是否来得及处理数据，避免发送方压垮接收方。
- 拥塞控制关注网络是否过载，避免大量发送方同时造成链路和路由器拥塞。
- TCP 面向连接，提供可靠传输、流量控制和拥塞控制；UDP 更轻量，常用于对实时性敏感或由应用自行控制可靠性的场景。

## 示例场景

浏览器访问 Web 服务时，客户端进程和服务器进程通过端口建立通信。TCP 负责把应用层数据可靠地交付给对端进程，并根据接收方能力和网络拥塞程度调整发送速率。

## 常见错误

- 把 IP 地址误认为能唯一标识一个应用进程。
- 混淆流量控制和拥塞控制。
- 认为 UDP 一定不可靠且不可使用。
- 只记 TCP 三次握手流程，不理解可靠传输的机制目的。

## 实操任务

- 画出客户端访问 Web 服务器时 IP 地址、端口和进程之间的对应关系。
- 用时序图描述 TCP 可靠传输中的确认与重传。
- 比较一次视频通话和一次文件下载为什么可能选择不同传输策略。

## 适合的学生画像

- 基础薄弱学生适合先学习“主机通信”和“进程通信”的对照图。
- 容易混淆机制的学生适合用流量控制和拥塞控制对比表。
- 实践型学生适合结合抓包结果观察 TCP 连接与端口。

## 测评建议

- 重点考查进程通信、可靠传输、流量控制、拥塞控制之间的职责边界。
- 用场景题检查学生能否选择 TCP 或 UDP 并说明理由。
