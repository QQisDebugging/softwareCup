# 第七章 应用层

## 7.1 本章导入

前面几章从下到上依次学习了物理层、链路层、网络层和传输层。物理层负责比特传输，链路层负责相邻节点之间传输帧，网络层负责跨网络传输分组，传输层负责进程到进程之间的通信。

应用层位于网络体系结构的最上层，直接面向用户应用。我们平时使用浏览器访问网页、发送邮件、登录在线系统、使用即时通信软件，本质上都是应用层协议在发挥作用。

应用层要解决的核心问题是：

> 应用进程之间应该按照什么格式、什么顺序、什么语义来交换数据。

例如，浏览器和 Web 服务器之间不能随便发送一串字符，而必须按照 HTTP 协议规定的格式组织请求和响应。只有双方都理解这些规则，通信才能正确进行。

## 7.2 应用层协议的作用

应用层协议定义了应用进程之间交换报文的规则。它通常包括以下内容：

| 内容 | 含义 |
|---|---|
| 报文格式 | 请求和响应由哪些字段组成 |
| 报文顺序 | 谁先发送，谁后回复 |
| 字段语义 | 每个字段代表什么含义 |
| 处理规则 | 收到某种报文后应该如何处理 |

可以简单理解为：

> 传输层负责把数据送到对端进程，应用层负责规定这些数据是什么意思。

例如，TCP 可以负责把浏览器的数据可靠地传给 Web 服务器，但 TCP 不知道这些数据是“请求首页”还是“提交表单”。这些含义需要由 HTTP 这样的应用层协议来定义。

---

## 7.3 Web 应用与 HTTP

Web 应用是最典型的应用层场景之一。用户在浏览器中输入网址后，浏览器作为客户端进程，Web 服务器作为服务器进程，二者通过 HTTP 或 HTTPS 交换数据。

HTTP 是 HyperText Transfer Protocol，即超文本传输协议。它采用请求—响应模式：

1. 浏览器向服务器发送 HTTP 请求。
2. 服务器解析请求。
3. 服务器返回 HTTP 响应。
4. 浏览器解析响应内容并显示网页。

一个简单的 HTTP 请求可以理解为：

```http
GET /index.html HTTP/1.1
Host: www.example.com
User-Agent: Browser
```

其中，`GET` 表示请求方法，`/index.html` 表示请求的资源路径，`Host` 表示目标主机名，`User-Agent` 表示客户端信息。

一个简单的 HTTP 响应可以理解为：

```http
HTTP/1.1 200 OK
Content-Type: text/html

<html>...</html>
```

其中，`200 OK` 表示请求成功，`Content-Type` 表示返回内容类型，响应体中包含网页内容。

---

## 7.4 HTTP 请求方法与状态码

HTTP 请求方法表示客户端希望服务器执行什么操作。常见方法包括：

| 方法 | 典型含义 |
|---|---|
| GET | 获取资源 |
| POST | 提交数据 |
| PUT | 更新资源 |
| DELETE | 删除资源 |

在基础学习阶段，重点掌握 GET 和 POST 即可。GET 常用于获取网页、图片、接口数据等资源；POST 常用于提交表单、上传数据或发送请求体。

HTTP 状态码表示服务器对请求的处理结果。常见状态码包括：

| 状态码 | 含义 |
|---|---|
| 200 | 请求成功 |
| 301/302 | 重定向 |
| 400 | 客户端请求有问题 |
| 403 | 服务器拒绝访问 |
| 404 | 请求资源不存在 |
| 500 | 服务器内部错误 |

学习 HTTP 时不能只记请求方法，还要理解请求头、响应状态码和报文结构。因为浏览器访问网页时，很多问题都可以通过观察这些信息进行定位。

---

## 7.5 DNS 的作用

人类更容易记住域名，例如 `www.example.com`，但网络层通信真正需要的是 IP 地址。DNS 的作用就是把便于记忆的域名解析为网络通信所需的 IP 地址。

可以简单理解为：

> DNS 负责把“网站名字”转换成“网络地址”。

例如，用户输入一个网址后，主机通常需要先进行 DNS 查询，得到目标服务器的 IP 地址，然后才能继续建立传输层连接并发送 HTTP 请求。

DNS 的基本过程可以概括为：

1. 用户输入域名。
2. 主机查看本地缓存中是否已有解析结果。
3. 如果没有，就向 DNS 服务器发起查询。
4. DNS 服务器返回域名对应的 IP 地址。
5. 主机使用该 IP 地址继续访问目标服务器。

需要注意：

> DNS 不负责传输网页内容，它只负责域名到 IP 地址的解析。

网页内容的获取主要由 HTTP 完成，底层还需要 TCP/IP 等协议配合。

## 7.6 DHCP 的作用

DHCP 是 Dynamic Host Configuration Protocol，即动态主机配置协议。它用于为主机自动分配网络参数。

一台刚连接网络的设备，通常还不知道自己应该使用什么 IP 地址，也不知道默认网关和 DNS 服务器是什么。如果要求用户手动配置这些信息，不仅麻烦，而且容易出错。

DHCP 可以自动为主机分配：

- IP 地址
- 子网掩码
- 默认网关
- DNS 服务器地址
- 地址租期等信息

可以简单理解为：

> DHCP 负责让新接入网络的主机获得“上网所需的基本配置”。

例如，笔记本刚连接校园 Wi-Fi 时，通常会先通过 DHCP 获取网络参数。获取成功后，它才知道自己在当前网络中的 IP 地址，以及访问外部网络时应该把数据交给哪个默认网关。

---

## 7.7 DNS 与 DHCP 的区别

DNS 和 DHCP 都是应用层协议，但它们解决的问题完全不同。

| 对比项 | DNS | DHCP |
|---|---|---|
| 主要作用 | 域名解析为 IP 地址 | 自动分配网络配置 |
| 输入 | 域名 | 新接入网络的主机请求 |
| 输出 | 目标主机 IP 地址 | 本机 IP、网关、DNS 服务器等参数 |
| 使用时机 | 访问域名时 | 主机接入网络时 |
| 典型问题 | “这个网站的 IP 是多少” | “我接入网络后该用什么配置” |

可以简单区分为：

> DHCP 解决“我自己怎么接入网络”，DNS 解决“我要访问的域名在哪里”。

这两个协议经常在一次网络访问过程中先后出现，但职责不同，不能混淆。

## 7.8 一次完整网页访问过程

以一台刚连接校园网的笔记本访问网站为例，整个过程可以按以下顺序理解。

首先，设备连接校园 Wi-Fi 或网线后，需要获得网络配置。此时 DHCP 服务器为设备分配 IP 地址、子网掩码、默认网关和 DNS 服务器等参数。

然后，用户在浏览器中输入域名。由于网络通信需要 IP 地址，主机会通过 DNS 查询域名对应的 IP 地址。

接着，浏览器进程根据目标 IP 地址和目标端口，与服务器进程建立传输层通信。如果访问的是普通 HTTP，常见端口是 80；如果访问的是 HTTPS，常见端口是 443。

之后，浏览器发送 HTTP 请求，服务器返回 HTTP 响应。浏览器接收响应内容后，对 HTML、CSS、JavaScript、图片等资源进行解析和加载，最终显示网页。

这个过程可以概括为：

1. DHCP 获取本机网络配置。
2. DNS 解析目标网站域名。
3. 传输层建立客户端进程与服务器进程之间的通信。
4. HTTP 发送请求并接收响应。
5. 浏览器解析并展示网页。

需要注意，实际网页访问可能还会涉及多次 DNS 查询、多条 TCP 连接、多个 HTTP 请求，以及缓存、重定向、HTTPS 加密等机制。基础阶段先掌握主流程即可。

## 7.9 示例：新设备接入网络并访问网站

假设一名学生带着新笔记本连接校园网并访问学校官网。

第一步，笔记本接入校园 Wi-Fi，但此时它还没有可用的网络参数。于是它通过 DHCP 请求网络配置。DHCP 服务器返回可用 IP 地址、子网掩码、默认网关和 DNS 服务器地址。

第二步，学生在浏览器输入学校官网域名。笔记本无法直接用域名进行 IP 层通信，因此需要向 DNS 服务器查询该域名对应的 IP 地址。

第三步，浏览器知道服务器 IP 地址后，与服务器对应端口建立传输层通信。若使用 HTTPS，通常会连接服务器的 443 端口。

第四步，浏览器发送 HTTP 请求，请求首页资源。服务器返回 HTTP 响应，响应中包含状态码、响应头和网页内容。

第五步，浏览器解析响应内容，继续请求网页中的图片、脚本、样式文件等资源，最终呈现完整页面。

这个例子体现了应用层协议之间的协同关系：DHCP 负责网络配置，DNS 负责域名解析，HTTP 负责网页数据交换。

## 7.10 常见误区

### 误区一：认为 DNS 负责传输网页内容

DNS 只负责把域名解析为 IP 地址。网页内容的请求与响应主要由 HTTP 完成。

### 误区二：混淆 DHCP 和 DNS

DHCP 解决主机接入网络时的自动配置问题，DNS 解决域名到 IP 地址的解析问题。DHCP 通常发生在设备接入网络阶段，DNS 通常发生在访问域名阶段。

### 误区三：只关注 HTTP 请求方法

HTTP 不只有 GET、POST 等方法，还包括请求 URL、请求头、请求体、响应状态码、响应头和响应体。分析 Web 通信时，应整体观察报文结构。

### 误区四：认为应用层可以脱离下层协议独立工作

应用层协议直接服务用户应用，但它仍然依赖传输层、网络层、链路层和物理层。HTTP 报文要经过 TCP 或 UDP、IP、链路层帧和物理信号才能真正传输。

## 7.12 本章小结

应用层是最接近用户的一层，直接服务具体网络应用。应用层协议定义应用进程之间交换报文的格式、顺序和语义，使浏览器、服务器、DNS 服务和 DHCP 服务等能够按照共同规则协同工作。

本章重点掌握三个协议：HTTP、DNS 和 DHCP。HTTP 负责浏览器和 Web 服务器之间的请求与响应；DNS 负责把域名解析为 IP 地址；DHCP 负责为新接入网络的主机自动分配网络参数。

理解应用层时，最重要的是把协议放入完整场景中分析。一次网页访问通常不是单一协议完成的，而是 DHCP、DNS、传输层连接、HTTP 请求响应以及下层网络传输共同配合的结果。掌握这一流程后，就能更清楚地解释“为什么电脑刚连上网要先获取地址”“为什么输入域名能访问网站”“为什么浏览器开发者工具能看到请求方法和状态码”等实际问题。
